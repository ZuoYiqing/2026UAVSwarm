# 怎么跟别人解释"运行时（Runtime）"

> 用途：对外沟通口径。按听众分档，附常见误解的纠正话术。
> 约束：**不要**把 Runtime 说成"运行环境"（那是 Python runtime，完全不同的东西）。

---

## 0. 先认清：这个词为什么难解释

| 常见理解 | 实际含义 | 冲突 |
| --- | --- | --- |
| **runtime = 运行环境**（Python runtime / JRE / .NET runtime） | 让程序跑起来的那套**底层支撑** | ⚠️ **完全不是一个东西** |
| **runtime = 运行时错误**（runtime error） | 跑起来才暴露的错误 | ⚠️ 无关 |
| **本项目的 Runtime** | 一个**任务执行与控制面**：裁决"能不能动"、派活给"谁去动"、把过程记下来 | ✅ 这才是它 |

**所以对外说话时，永远不要只说"runtime"三个字。**
加上限定词：**"任务运行时"** / **"Runtime 控制面"** / **"我们的执行运行时"**。

---

## 1. 三档说法（照读即可）

### 1.1 十五秒版（对领导、对完全不懂的人）

> **"它不负责飞，负责决定'该不该飞、谁批准、飞完记不记得'。"**

如果还要再短：

> **"飞机是手脚，它是大脑里管纪律和记账的那部分。"**

### 1.2 一分钟版（对同事、对合作方）

> "打个比方：**它是机场塔台，不是飞机。**
>
> 塔台自己不会飞，但飞机能不能起飞、能不能降落、几号跑道、什么时候，都是塔台说了算；而且塔台**全程留记录**，事后能查谁在几点几分批准了什么。
>
> 我们这个东西也一样：
> **它不控制电机，但任何动作都必须先经过它批准**，它会判断——链路通不通、目标合不合法、这个动作危不危险——批准了才交给下面真正开飞机的程序去做，做完还要落一条记录。
>
> 关键的一点：**它拒绝的时候，是真的连一条命令都没发出去**，不是"发了但没成功"。"

### 1.3 五分钟版（对工程师、对评审）

按这个顺序讲，讲完对方基本能复述：

**① 它解决什么问题**

> 飞控（PX4）只负责"怎么动"——姿态、电机、速度。
> 但**"该不该动、谁允许动、动完有没有据可查"没人管**。
> 单机还可以人盯，多机就会出现：谁先动、会不会互相撞、失联了谁负责停车、出事了怎么复盘。
> **这些都需要一个统一裁决的地方。**

**② 它在链路里的位置**

```
操作台 / 智能体
      ↓  提一个"结构化请求"（不是协议帧）
  ★ Runtime ★    ← 裁决 / 派发 / 记账
      ↓  翻译成具体协议
  飞控 / 底盘    ← 真正动电机
```

**③ 它做的三件事**

| 事 | 具体内容 |
| --- | --- |
| **裁决** | 允许 / 拒绝 / 需要人工确认。拒绝时给出**理由码**（不是"失败了"三个字） |
| **派发** | 把"去某点"翻译成具体载体能懂的命令；同一动作重复提交只执行一次（幂等） |
| **记账** | 每一次动作落两条审计记录：谁批的 + 结果如何。可回放 |

**④ 它和载体无关**

> 换无人机、换地面车、换别的载具，**裁决和记账这一层不用改**，只需要换一个"翻译层"（我们叫适配器）。
> 所以它不是"某台飞机的配件"，是**一套可以跨载体复用的控制面**。

## 2. 最好用的一个真实例子（30 秒说服人）

> "我们做过一次演示：让它**降落**，但把**通信链路设成已失联**。
>
> 它回了三个东西：
> - **拒绝**
> - **理由**：链路已丢失，而"普通降落"不是一个适用于失联状态的兜底动作
> - **适配器字段是空的**
>
> 最后这一条是关键 —— **空的意思是我们一条命令都没往飞机上发**，不是发了没人理。
> 如果这一层是摆设，那里会写着'已发送'。"

**为什么这个故事强**：它同时证明了裁决、理由、以及"拒绝是真拒绝"。

## 3. 别人一定会猜错，这样纠正

| 对方说 | 你要说的是 |
| --- | --- |
| "是不是就是自动化脚本？" | "不一样。脚本是**照做**；它是**先判断该不该做，再决定做不做，做完留证**。脚本没有'拒绝'这个状态。" |
| "是不是就是个消息中间件/转发器？" | "转发器只搬运。它**要裁决**——同样的消息，链路正常时放行，链路断了就挡下，而且理由不一样。" |
| "是不是 API 网关？" | "网关管'谁能调这个接口'。它管'**这个动作在这个时刻该不该被执行**'——判断依据包含飞行状态、链路状态、风险等级，不只看权限。" |
| "是不是 ROS 那种东西？" | "ROS 是**通信框架**，负责让各个程序互相说话。我们这层是**决策与责任层**。而且我们的控制链路**不依赖 ROS**。" |
| "那不就是 Python 运行环境吗？" | "**不是。** 我们说的是'任务运行时'，是业务概念，不是语言层面的运行环境。这是中文撞名，容易误会。" |
| "为什么不用飞控自带的功能？" | "飞控管执行，不管**跨机协同**和**责任追溯**。飞控不会告诉你'这次降落是谁批准的、为什么当时允许'。" |

---

## 4. 绝对不要说的几种说法

| ❌ 不要说 | 为什么 |
| --- | --- |
| "就是个中间层" | 听起来像可有可无的转发，把核心价值说没了 |
| "就是个调度器" | 调度器不含裁决与审计，容易被理解成负载均衡 |
| "运行环境" | **直接撞上 Python runtime，是最坏的误解** |
| "负责控制飞机的程序" | 它是**不**直接控制飞机的那个；说反了会让人以为它在飞控里 |
| "AI 大脑" | 它**不含任何机器学习**（这点我们查证过：零模型、零推理）；说成 AI 会引来错误的期待 |

---

## 5. 一句话记忆锚点

> **"它是那个说'不'并且留下证据的东西。"**

对外沟通里，这句比任何技术定义都管用 —— 因为普通人最容易理解"有人能拦下你，而且拦下你这件事有记录"。

| 项 | 数值 |
| --- | --- |
| 代码规模 | 17 个子包，13,554 行 Python |

| 裁决结果 | 允许 / 拒绝 / 需人工确认（三态，不是布尔） |
| 审计 | 每次动作 2 条记录（真实载具路径 6 条），可回放 |
| 是否含 AI/模型 | **不含**。裁决是确定性规则，可逐条读成人话 |
| 载体相关性 | 与载体无关；换载具只换适配器 |

### 6.1 "不含 AI" 这一条的实证（可放心对外说）

对 `src/uav_runtime/` 全量检索：**没有任何 ML 库、没有模型推理**。
第三方 import 只有 `pymavlink` 一个（其余全是标准库）：

```
__future__ argparse collections copy csv dataclasses datetime enum hashlib
http importlib json math os pathlib pymavlink re threading time typing
uav_runtime urllib uuid
```

而且源码注释里自己就写明了边界：

> `agent/planner.py:6` — "It does not parse free-form natural language, **call an LLM**, execute runtime…"
>
> `agent/planner.py:180` — "**This is not LLM reasoning** and not a scheduler."

**结论**：Runtime 的裁决是**确定性规则**，不是黑盒。这一点在对外解释时很有用 ——
因为"能不能追溯是哪条规则拒了"是这层的核心价值，黑盒会摧毁它。
（模型/大模型实验在 `algorithm_lab/`，**不在控制链路里**。）
