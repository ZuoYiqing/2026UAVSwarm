语料规范化哈希：`07b569340306dc331e859d83b3f7a493783024df7ef81808a48d909e9207c331`。
每轮逐题请求：seed=0、temperature=0、ctx=4096、max_output=1024、JSON schema 约束、关闭思考、无修复/自动重试。
节点分配仍由规则基线完成，因此不能把绑定模型成绩称为模型多机分配成绩。

| 方法 | 轮数 / 请求数 | 每轮候选语义匹配 | 每轮接受/拒绝与标注一致 | 每轮实际接受数 | 错误放行 |

| 精确标签规则基线 | 无模型 | 5/8 | 9/9 | 4/9 | 0 |
| 0.8B 原提示词 v1 | 3 / 27 | 3/8 | 6/9 | 1/9 | 0 |
| 0.8B 显式开发提示词 selective_v2 | 3 / 27 | 5/8 | 8/9 | 3/9 | 0 |

“接受判定一致”包括正确拒绝，不能称为任务成功率。错误放行 0 只限这 9 条样本，不是安全证明。
v2 根据 v1 在这组题中的错误设计，属于开发集提示词消融，不是独立测试集上的泛化提升。
每种提示词三轮的逐案例规范化候选哈希一致；不保证不同引擎、硬件或输入下确定性。
默认提示词仍为 v1，v2 必须显式选择；未改输出契约、未修改答案或降低验收门槛。

代表性错误：

- v1：只去 A 却输出 A+B；B 区文本包含“前往”导致需要语义审核；B→A 输出重复且乱序；否定 B 仍选择 B。
- v2：B 区、正反序、否定选择有所改善，但“只去 A”仍多选；东部别名绑定到两个区域；巡检时把标签 A区 当作 region_id。
- 未知区域：现有 schema 要求至少一个 binding，不能表达无匹配/澄清；当前只能靠校验拒绝，并从语义匹配分母排除。
  这是实验输出设计缺口，不应把被 schema 迫出的错误区域全部归因于模型。下一轮需要独立设计候选拒绝/澄清结果。

## 三机结构化提案

另对 `examples/three_uav_inspection.json` 显式请求两次，同为 1024 输出 token。
两次都得到 `finish_reason=length`，都拒绝；不得把部分文本解析成完整计划。
第二次保存的原文显示解释反复循环，未完整输出。延长预算不等于解决循环，所以未自动提高预算重试。
首次失败仅保留错误、引擎日志和资源记录，原响应正文当时丢失；本轮发现并修复这一记录缺口，显式复跑后保存完整有界响应证据。
失败诊断始终 `accepted=false`、`proposal=null`、`execution_authorized=false`，CLI 返回 2。

总计：54 次完成的语义请求 + 2 次三机提案截断响应；不是 56 次成功规划。

## 实测资源与耗时

- 六轮语义整轮墙钟：9.56、25.52、30.11、15.58、16.79、14.95 秒；同一电脑存在负载变化。
- 原提示词 27 次请求中位耗时约 2.16 秒，范围 0.80–8.90 秒；v2 中位约 1.69 秒，范围 1.03–2.27 秒。
- 六轮语义 GPU 总占用点样最大 688 MiB、温度最高 56°C、主机可用内存点样最小约 3.18 GiB。
- 保存正文的三机请求墙钟约 7.82 秒，模型输出 1024 token，未完成。

上述 GPU 数字包含桌面等其他进程，不是模型独占显存；点样不是可靠瞬时峰值，也没有首 token 时延测量。
启动后持续采用低于 1.5 GiB 可用主机内存或达到 85°C 即停止的保护。
0.8B 启动预算为 3 GiB RAM / 2048 MiB GPU 空闲，这只是实验准入值；4B 原 5 GiB / 4608 MiB 门槛未降低。
未触发资源保护；试跑结束已停止本实验服务，不关闭用户其他程序。
该 0.8B 推理实验当前不需要租服务器；大规模训练/微调是否租卡要单独做预算。
