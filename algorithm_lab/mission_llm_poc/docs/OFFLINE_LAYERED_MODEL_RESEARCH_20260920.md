# Algorithm Delivery Report — Offline Layered Model Research v0.1

研究日期：2026-09-20。证据等级：本仓库实测 / 作者或厂商报告 / 待验证建议，三者不可混用。
本报告属于Algorithm Lab选型研究，不冻结系统架构、三层指控拓扑或Runtime契约。

## 1. Problem — 要解决什么

在完全离线的部署条件下，使地面任务理解、集群任务协同、单平台感知与局部决策分别使用合适算法。
优先证明“小模型确实带来任务语义能力”，而不是再建聊天界面或替换已有控制台。

部署不得调用闭源云模型，不允许云端回退。租用计算资源仅用于用户批准的准备、训练、量化和评测；
任务现场不得依赖租用服务。外网调研、制品准备不等于现场联网运行。
设备间专网通信与互联网依赖是不同问题；机间通信断开也必须有独立验收。

## 3. Outputs — 算法交付与适配器解释

当前实验输入是Mission Context + 已给定的任务/航点清单 + Fleet状态；
输出是经过本地校验的Mission Proposal，execution_authorized始终为false。
输出通过校验不代表轨迹安全、任务可执行或得到Policy授权。

client = 程序调用本地推理的适配器，不是聊天前端，不是模型，不等于Ollama。
模型权重是数据，推理引擎负责计算，适配器传递输入/输出；已有控制台保持不变。

当前可选HTTP适配器只允许显式本机回环地址，禁代理/重定向/工具调用，无云回退。
也可在将来新增同进程C++/Python或厂商SDK后端，但目前未实现，不能宣称已支持。
llama.cpp支持C/C++、命令行与本地服务；无需额外聊天界面。[官方仓库](https://github.com/ggml-org/llama.cpp)

无人机部署位置应是伴随计算机，不是PX4飞控MCU。即使采用同机HTTP，也只在本机进程间传数据。
当前适配器不支持跨机器地面服务；将来若需专网服务，必须另提网络、认证、时限和断链契约。

## 4. Algorithm / Model — 分工与候选池

### 4.1 能力分工

| 能力 | 首选基线 | 模型的必要性 |
| --- | --- | --- |
| 任务语义、意图、解释 | 结构化表单/受限语法 + 小LLM对照 | 自由中文有价值，不能替代约束检查 |
| 区域划分、任务分配 | 几何分割、确定性greedy、Hungarian/auction | LLM提建议；成本与可行性由算法计算 |
| 局部搜索、轨迹与冲突 | A*、覆盖规划、几何轨迹优化 | 不默认需要LLM/RL |
| 检测、跟踪 | 专用小CV模型 + 经典跟踪器 | 常驻检测与低频VLM复核分开 |
| World State | 对象/地图/轨迹 + 时间戳/置信度/来源 | 先做结构化时序状态，不先上生成式世界模型 |
| 通信受限协同 | 有界消息、版本化任务、超时/租约等协议实验 | 语义模型不拥有状态同步权威 |
| RL/MARL/视觉策略 | 在上述基线后做离线仿真比较 | 必须有任务数据、消融及明确收益 |
| 飞行实时控制 | 现有确定性飞控 | 本阶段不进入算法实验执行链 |

| [PP-PicoDet-XS/S](https://github.com/PaddlePaddle/PaddleDetection/blob/develop/configs/picodet/README.md) | 权重/导出物可得；[代码Apache-2.0](https://github.com/PaddlePaddle/PaddleDetection/blob/develop/LICENSE)；XS0.70M/S1.18M参数 | 常驻目标检测；须用航拍小目标数据验证，不能泛化识别任意语义 |

4B量化文件是第三方转换制品，不称为官方量化；下载前固定revision、SHA256和来源。
文件大小不等于运行显存，还需KV/状态缓存、计算缓冲、视觉编码器、驱动和其他进程。
优先从短上下文、batch1开始实测；上下文上限不是推荐部署值。资源不足先降2B，不先采购或租卡。
最新版不自动等于最适合本项目，最终选择依据相同UAV benchmark的质量—延迟—功耗结果。

### 4.3 按硬件条件分档，而不是按TOPS分配模型

| 资源档（条件示例，不是最低配置保证） | 候选组合 | 首先验证 |
| --- | --- | --- |
| 当前4050/6GB + 16GB RAM | 4B Q4文本；2B对照；通过后再加单图 | 加载峰值、可用RAM、长输出、显示/其他GPU任务争用 |
| 更强地面工作站 | 9B至24/27B等模型按实际显存选；CV分开 | 完整上下文与视觉占用、并发、断网冷启动 |
| 50–200 TOPS且有充足RAM/带宽/兼容后端 | 2B低比特VLM起测，4B作为上探；CV与规划独立 | 算子覆盖、持续功耗、热降频、感知竞争 |
| 约20 TOPS或更低但有可用NPU/GPU、数GB RAM | 专用CV常驻；0.8B/小VLM事件触发 | 厂商转换链、完整视觉内存、首响应时延 |
| 极弱CPU/MCU、RAM很小或无模型后端 | 状态机、已验证几何/控制算法；有条件才运行小CV | 断链时无需语言模型仍能维持授权范围内的行为 |

以上内存描述仅筛选方向。INT4/INT8/FP16、稀疏/稠密TOPS不能直接横比，更不能换算token/s。
ARM64只说明CPU架构，llama.cpp在ARM上可运行不代表能使用板上NPU。
NVIDIA路线需核实CUDA后端；Rockchip需RKNN视觉编码器和RKLLM语言运行时等匹配制品。
厂商库的分发许可、板卡驱动和算子支持须在定硬件后单独审核。

[Rockchip官方benchmark](https://github.com/airockchip/rknn-llm/blob/main/benchmark.md)给出
RK3588上Qwen3.5-0.8B的448×448图像编码690ms、216-token prefill1.56s、decode27token/s；
语言侧w8a8，视觉编码器RKNN FP16，最高CPU/NPU频率。
这证明特定较弱板卡值得试，不证明本项目达标；短文本表的约1039.66MB不能当完整VLM内存。
其秒级语义处理不能代替高频避障。[部署与C API](https://github.com/airockchip/rknn-llm)

## 5. Alternatives Compared — 用户参考与GitHub筛选

### D-VLC

[论文v2](https://arxiv.org/html/2607.29009v2)：两无人机加移动机械臂，Unity/ROS1仿真。
五种模型总体成功率76.7–90%，几何贪心66.7%；每种方法30次。
55.8%耗时下降是论文中完成时间最短的模型配置377.2→166.8秒，且只统计成功试验；
该配置成功率76.7%，最高成功率90%属于另一配置，不能称作各项指标综合最优。
基线仍共享视觉语言检测/定位。不是离线小模型机载成绩。
论文将真机、丢包/延迟压力测试列为后续工作；未核实作者官方代码发布。
借鉴能力约束、异步协同和任务状态；需要用本地模型重新验证，不直接搬作产品栈。

### Patch Policy

[论文](https://arxiv.org/html/2607.18236v1)、[官方代码](https://github.com/gaoyuezhou/patch_policy)。
0.7%对应51.55M总参数与7.61B基线的比值，不表示所有配置；10.99ms测于H200。

尚未确认，各任务指标并不统一，不能转述成所有任务统一成功率提升18个百分点。
验证场景是机械臂操控，不是无人机导航。冻结视觉主干仍需任务数据训练策略。
[代码MIT](https://github.com/gaoyuezhou/patch_policy/blob/main/LICENSE)，主干权重另审；未确认可直接部署的通用策略权重。
适合作后续轻量策略研究，不能把“小参数”解释成4050能直接跑默认训练或弱板卡已达标。

### FlyCo

第一实验：离线小模型能否根据中文任务与可信Fleet Context生成合规的任务分配提案？
不同时扩展图像输入、Runtime接入和真机执行；先让用户看清真实模型相对规则的增益。

1. 审批精确制品清单：模型revision/量化/文件SHA256、推理引擎版本及许可证、目录、磁盘预算。
2. 在准备环境取件；不改根依赖，不向Runtime环境安装模型框架。
3. 断网环境本地冷启动，batch1、初始上下文4096token、输出最多1024token；设置为待验证实验配置。
   正式跑前记录实际token数；超限明确失败，不静默截断任务。必须验证模型模板与schema约束兼容。
4. 先用4B Q4跑现有22个模型任务，记录原始文本、拒绝、校验、耗时和显存。
5. 再增加并独立报告至少20条人工标注中文样本：同义表达、否定、优先级、歧义、文本/结构化冲突。
   当前代码不会自由生成任务图，不能用现有22例宣称意图理解准确率。
6. 在相同样本/配置下比较2B；规则分配结果只作为结构化可行性对照，不伪装成NL模型。
7. 通过后单开VLM实验：本地图像→语义目标proposal→独立空间/几何检查，不能直接输出电机控制。
8. 向Integration Owner交付原始结果、制品清单、失败案例和候选接口；是否接主系统由其决定。

## 7. Failure Cases — 不能省略的风险

- 结构正确但语义错；模型建议与任务文本、真实遥测、地图版本冲突。
- 小模型长思考挤占输出预算，截断JSON；量化后质量下降或模板不兼容。
- VLM把像素目标当作米制坐标，忽略相机标定、深度、遮挡或目标不确定性。
- 权重能加载但持续并发OOM/热降频，模型拖慢CV/规划，过期提案仍返回。
- 地面通信失效时等待地面LLM导致机载任务阻塞；不能默认为模型会安全返航。
- “本机服务”代理到互联网；缓存齐全时测试通过而离线冷启动失败。
- TOPS相近的板卡因不支持算子而退回CPU，性能与功耗完全不同。

## 8. Safety / Boundary — 离线与飞控隔离

所有LLM/VLM/RL结果都是不可信proposal。确定性检查后仍须Runtime重新验证状态和Policy。
算法不发送MAVLink，不定义UDP endpoint，不触碰飞控motor/PWM，不修改Policy。
失联后的悬停/返航/降落等行为选择属于已批准的系统策略，本文不自行规定或执行。

跨机计算只使用带scene/map/标定有效性保证的scene_ned，禁止比较各机vehicle_local_ned。
当前Runtime公共位置应读取spatial.scene_pose并检查public_position_usable等有效性；
算法不以机身yaw猜测坐标变换，也不把-down当作AGL或MSL。

离线验收须包括：本地权重/分词器/处理器/模板/驱动/依赖包齐全；
关闭自动下载、自动更新、可选遥测和外部工具；在部署隔离网络验证。
本适配器限制回环访问并不能证明未来引擎无出站网络。缺文件必须失败，不静默联网补齐。
不承诺第三方包或许可证文本完全没有某厂商名称；不得为命名要求篡改第三方许可证。
