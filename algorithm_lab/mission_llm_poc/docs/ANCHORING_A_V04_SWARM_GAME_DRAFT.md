# A-v0.4 题面草案：三机巡检预演与虚拟棋盘竞赛

状态：**12 条公开例题已做过规则/本地模型对照和规则复验，不是冻结的盲测集。** A-v0.3 的 30 条旧题和原始记录不变。这批题只测自然语言实体指代：找出原话说的是哪个目录对象、按什么顺序、多项是否缺漏。园区例题可以在隔离目录走 Runtime 只读预览；不生成航点、控制指令或载具分配，不提交执行。棋盘仍是独立的虚拟记分题域，不接 Runtime。

## 和上一轮保持不变的东西

输入仍为一条 `objective` 和当前唯一有效的带版本实体目录（`scene_id`、`map_version`、`entities`）。模型不看标准答案。输出仍用 `status` + `bindings[]`，绑定的每项只含 `entity_id` 和逐字来自指令的 `evidence`。`bound` 要求全部目标确定；`clarify` 表示可选目标不唯一或指代不足，`unknown` 表示明确要求的目标不在目录。后两种都不能交部分答案或猜一个 ID。型号、节点名、赛况可以出现在话里，但此版不评分调度和策略。

可用任务提示草案：

> 你只负责读懂巡检预演或棋盘复盘里点名的对象，不执行任务。只使用当题提供的实体目录。选出被要求核对或记录的全部对象，忽略参照物、背景赛况和明确排除项。按指令要求的顺序输出实体 ID，证据须逐字摘自指令。若对象不唯一，返回 `clarify`；若任一必需对象不在目录，返回 `unknown`。不编造、不给部分绑定。


### 园区题解和规则复验（2026-11-24）

- **S01 前缀**：只移除白名单中的语气词、时间提示或完整的「三机联巡任务预演：」标题，保留「只」和实际对象。「请帮我巡检西侧光伏区」与原题都只绑定 `S-PV-W`。标题不生成分工。
- **S02 改写**：「西面那排用于发电的太阳能板」按完整词法结构与目录中的西侧光伏名称匹配，证据保留原话。非定指的「那排发电板」「机房」必须在所属类中只有一个候选；「北边的仓库」用明确的方向和仓库名称匹配。不会把「空调机房」近似匹配成热泵机房。
- **S03 / S06 不猜**：两个同名水表点必须追问，缺少东侧充电棚时保留 `unknown`，不提交已知对象的子集。裸指代「这个／那栋／刚才说的那个」只在调用方提供当前目录内唯一指代上下文时解析；否则追问。直接使用现有 Runtime 原话入口时没有该上下文。
- **S04 角色分离**：只绑定 `S-THERM`；北仓保留为 `reference_only` 和 `excluded_targets`，不能随着改写或指代变成目标。
- **S05 顺序**：「X 之前，先 Y」「先 Y，再 X」「Y 之后 X」按完整句式识别，输出光伏区 → 机房，并由算法结果标为 `target_order_basis=explicit_sequence`。并列目标没有先后词时按原话出现顺序，标为 `mention_order`，不声称这是显式执行顺序。句式不完整或约束冲突，不产部分绑定。

用与上轮完全相同的 12 条原话和目录，园区规则从完整绑定 **1/4 → 4/4**、顺序 **0/1 → 1/1**；两类合看，应澄清却错绑仍为 **0/2**，未知状态匹配 **2/2**。园区验收是隔离进程把算法原件临时接入现有 HTTP 预览，所有回包未授权执行。本次没有运行模型；Runtime 的 vendor 副本和 HTTP 字段都没改，`target_order_basis` 目前是算法输出字段，不是已发布的 HTTP 字段。棋盘记录类任务仍不在这版规则支持范围。

## 怎么测，才知道差异从哪来

1. 上面 12 条是**供人审阅的例题**。定稿时再用独立词汇/场景编正式测试题，不用已公开的这些例题同时做提示示范和评分题；为每题写清对象、顺序和证据。旧 A-v0.3 保留为跨题域参考。
2. 对照时先用同一套契约、题集、解码约束和规则基线测模型。若专门比较“换成巡检措辞是否有帮助”，应另设原任务提示和领域提示的同题对照；不要同时换题、换模型、换提示，然后把差异统归为模型更强。
3. 主看正确完整绑定、顺序、应澄清/未知却错绑、有效输出中的弃答。按两类题域分别报分，保留逐题原始输出；合法 JSON 不算语义正确。
4. 如要测**多智能体协作或博弈能力**，再单开小型无伤害棋盘实验：给出公开棋盘状态和规则，比较规则策略与模型提出的候选，在模拟裁判下单独测合法率、同队重复选择率和得分。例：“两枚蓝方棋子各选一张记分牌；甲牌 3 分、乙牌 2 分，重复选择同一张只算一次。请给出两枚棋子的候选选牌和预期总分。”这个数字题能检验是否重复分配；双方选择会影响可得分数的回合另设题，不把这道题当对抗效果。两者均不接真实平台。
